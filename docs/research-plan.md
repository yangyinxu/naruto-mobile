# B站《火影忍者手游》玩家反馈调查方案

> 本文从原 ChatGPT 对话恢复并整理。研究范围专指腾讯《火影忍者》手游，不是动画、漫画或整个火影 IP。文中示例数字用于说明报告格式，不代表当前真实玩家反馈。
>
> 实施说明（2026-08-26）：研究方法和口径继续保留；技术实现已按确认方案更新为 Node.js + TypeScript + React/Vite + 本地 JSONL，不依赖 MongoDB、SQLite 或远程服务器。

## 一、插件与采集方式结论

第一阶段不需要安装插件。一次性研究或小规模 MVP，可以采用浏览器辅助采集、表格或数据库和分类器；长期自动监控时，再建设自有合规采集适配器或采购合规数据服务。

生产环境优先考虑 B站开放平台、获准的数据服务商或人工研究导入。不要依赖来源不明的爬虫插件，不绕过登录、验证码、访问限制或反自动化机制。采集方式必须遵守平台条款和适用法律。

## 二、研究要回答的问题

不要只问“B站用户对火影忍者手游是正面还是负面”，而要回答：

| 研究问题 | 产品价值 |
|---|---|
| 最近玩家主要在讨论哪些问题 | 发现热点和新问题 |
| 哪些话题正在快速升温 | 提前识别口碑风险 |
| 玩家具体在不满什么，为什么 | 定位产品根因 |
| 不同类型玩家态度是否不同 | 确定受影响用户群 |
| 哪些意见会影响抽取、充值、留存或退游 | 确定优先级 |

默认窗口：最近 7 天用于实时观察，最近 30 天用于主报告，之前 90 天作为趋势基线。版本事件取更新前 3 天至更新后 7 天；平衡调整在更新后 24 小时、3 天和 7 天分别复盘。

## 三、采集对象

### 视频层

保存 BV号、标题、简介、标签、发布时间、UP主账号类型、播放/点赞/投币/收藏/评论/弹幕数、搜索命中词和视频类型。

视频类型：

1. 官方爆料、版本公告、活动公告
2. 新忍者测评和强度分析
3. 决斗场数据、段位环境分析
4. 教学、连招、打法和阵容
5. 氪金、抽取和性价比讨论
6. 吐槽、Bug、服务器问题
7. 实战、高光、娱乐和整活
8. 新手入坑、回坑、退坑相关内容

版本事件和忍者平衡调整是重点触发器，不能只搜索游戏名称。

### 用户意见层

优先级：视频一级评论、高赞评论的回复楼层、最新评论、弹幕、视频标题和UP主观点、直播切片或录播评论。标题属于创作者观点，评论和弹幕属于观众反应，两者必须分开存储和分析。

## 五、相关性判断

- 高相关：标题、简介或标签直接包含“火影忍者手游”或“火影手游”。
- 中相关：忍者名称与决斗场、高招、忍法帖、点券、削弱/加强等手游语境共现，或魔方与忍者/策划/版本共现。
- 低相关：只有鸣人、佐助、鼬等角色名，没有手游语境。

生产分析只使用高相关和复核后的中相关。低相关可留在原始层，但不进入正式报告。

## 六、采样方案

每天分别观察按最新发布排序、综合/热度排序、重点UP主、官方公告和版本视频、突然快速增长的视频。

评论少于 200 条时可全量；超过 200 条时，初始采集高赞 50、最新 50、分页均匀抽样 50–100、高赞评论前 10 个讨论楼层、沿视频时间轴均匀抽取弹幕 100–300 条。

控制偏差：

- 单个视频最多占周样本 10%
- 单个UP主最多占周样本 15%
- 同一用户重复评论合并或降权
- 转发、复读、抽奖和纯表情单独标记
- 同一观点被多个视频搬运时做语义去重

第一轮建议 100–150 个相关视频、3,000–5,000 条有效评论、2,000–4,000 条弹幕、500 条人工标注，覆盖最近 30 天。

## 七、火影手游专用主题

| 一级主题 | 二级主题 |
|---|---|
| 忍者设计 | IP还原、机制创意、技能设计、特效、模型、奥义、手感、完成度 |
| 忍者强度 | 超标、弱势、保值、削弱、加强、强度与获取成本是否匹配 |
| 决斗场体验 | 匹配、段位、上分、替身、技能判定、秘卷、通灵、环境多样性 |
| 公平性 | 付费忍者优势、旧忍者淘汰、操作与数值关系、外挂、代打 |
| 商业化 | 高招、点券、直购、忍法帖、礼包、抽取成本、保底、返场 |
| 活动与福利 | 金币、忍者碎片、签到、周年庆、补偿、活动肝度 |
| 新手与回流 | 入坑门槛、追赶成本、回归体验、学习成本 |
| PVE与玩法 | 幻之试炼、组织玩法、剧情、日常、玩法重复度 |
| 技术质量 | 卡顿、延迟、掉线、闪退、Bug、机型适配、服务器 |
| 运营沟通 | 策划回应、公告透明度、补偿态度、玩家信任 |
| IP体验 | 情怀、角色还原、音乐、美术、剧情记忆 |
| 行为意图 | 必抽、不抽、充值、停止充值、回坑、继续玩、退游 |

主题允许多选，情绪也必须按主题输出。例如“这个忍者做得真帅，但是强度也太超标了”应得到忍者设计正面、忍者强度负面。

## 八、分析标签

每条有效意见至少生成：相关性、主题、实体、主题级情绪、情感、立场、严重程度、行为意图、玩家分层、可行动性和置信度。

玩家分层只能由明确表达判断。例如“我是V0”标记零氪，“玩了八年”标记老玩家，“刚回坑”标记回流，“常年超影”标记高竞技玩家。不要根据语气或用户名猜测年龄、消费能力和段位。

## 九、玩家分层

至少保留新玩家、回流玩家、老玩家、决斗场玩家、PVE/收集玩家、零氪玩家、低付费玩家、高付费玩家和内容创作者等维度。报告不一定每次展示全部分层，数据库要支持。

## 十、指标

1. 话题占比：某主题有效意见数 / 全部有效意见数。
2. 净态度值：`(正向意见数 - 负向意见数) / 该主题有效意见数`，按主题计算。
3. 讨论增长率：最近 7 天主题占比与前 7 天主题占比比较，同时看绝对数和占比。
4. 风险分：独立意见作者数 × 负面比例 × 严重程度 × 近期增长系数 × 行为影响系数。
5. 行为影响系数：普通吐槽 1.0，明确不抽 1.3，停止充值 1.6，退游或卸载 2.0。
6. 同时展示独立用户口径和传播影响口径；点赞权重设上限，不能把一万点赞等同于一万名玩家。

## 十一、异常预警

- P0：服务器、登录、掉线或闪退短时间超过基线 3 倍，来自至少 3 个不同视频或UP主，并出现退游、卸载、充值损失或晋级赛异常。
- P1：新忍者上线 24 小时负面超过 60%，3 天后仍未下降，且集中在机制、强度、虚假预期或付费公平性。
- P2：忍者或玩法话题增长超过 100%，但数量不足或主要由一个视频驱动。

每条警报附带：发生了什么、开始时间、受影响玩家、至少三个独立来源、代表性原话和建议责任团队。

## 十二、最终报告

每周报告为一页摘要加附件。首页包含一句话结论、增长最快三个话题、负面风险最高三个问题、最受认可内容、充值与流失意向变化和产品行动。

忍者评分卡展示设计认可、强度评价、公平性、抽取意愿和主要问题。重点问题卡统一展示变化、受影响群体、主要表现、行为风险、证据和建议负责人。所有数字必须来自真实采集，不能把格式示例当成结论。

## 十三、技术架构

MVP：

```text
B站公开搜索与观察列表
  → Playwright 低频浏览器辅助采集（可替换适配器）
  → 只追加原始 JSONL + 原子检查点
  → 去重与相关性过滤
  → 可审计规则词典多标签分类
  → Markdown 报告与质量报告
  → Express 本机 API
  → React 网页调查台与报告页
```

当前 MVP 使用 Node.js 24、严格 TypeScript、Express、React、Vite、Playwright 和 JSON/JSONL 文件。Express 固定监听 `127.0.0.1`；Vite 只负责开发和构建，正式运行时由 Express 提供静态网页。单机、单用户和当前数据量不需要数据库，也不要求 AI API、Kafka、向量数据库或复杂微服务。

后续只有在多用户协作、长期定时监控、跨大量调查聚合或百万级查询出现时，再评估 MongoDB、DuckDB、SQLite 或分析数据库。生产版可以增加获准数据源、模型分类适配器、人工标注台、聚类和趋势检测、告警与周报调度。

## 十四、明文溯源与治理

- 原始层以明文保存页面公开的昵称、UID、评论 ID、父评论 ID、正文、公开用户主页、来源页/直达链接、发布时间和采集时间
- 用户名与评论保存在同一记录中；分类结果通过稳定意见 ID 回指原始记录
- 加盐作者哈希只作为兼容旧版本的附加去重键，不替代明文 UID
- 工具不采集公开 IP 属地等本研究不需要的额外画像字段
- 报告默认不展示可识别普通用户身份的信息，但本地原始证据可逐条核查
- 工具不自动删除或加密原始评论；使用者负责目录访问、备份、分享和保留周期
- 被删除或不可访问的内容可以保留为当时采集的历史证据，但对外引用时应标明当前不可访问
- 对外报告优先概括，不大段复制用户原话

研究对象是意见模式，不是追踪具体玩家。

## 十五、14天 MVP 计划与验收

| 时间 | 任务 |
|---|---|
| 第1–2天 | 关键词、排除词、UP主观察列表和主题分类 |
| 第3–4天 | 最近30天 50–100 个视频和首批评论 |
| 第5–6天 | 人工标注 500 条，形成标准答案集 |
| 第7天 | 调整相关性、主题、情绪和行为意图分类 |
| 第8–11天 | 每日增量采集，测试趋势和异常预警 |
| 第12天 | 人工复核高风险主题和代表性证据 |
| 第13天 | 第一版 Dashboard |
| 第14天 | 周报和长期建设决策 |

验收标准：相关性人工抽检准确率 95%，一级主题准确率 85%，高风险结论至少有 3 个独立视频来源，意见可回溯到原视频和采集时间，报告产生至少 3 个产品行动建议，产品经理 5 分钟内理解本周主要问题。

默认启动配置：最近 30 天、100–150 个视频、3,000–5,000 条评论、500 条人工标注，以周报为主要输出，以版本更新和新忍者上线为事件触发。
