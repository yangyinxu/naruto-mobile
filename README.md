# 火影手游玩家反馈调查工具

一个完全在本机运行的 B站《火影忍者手游》玩家反馈调查 MVP。用户通过中文网页创建调查，工具优先浏览热门视频和动态，收集公开意见，支持暂停、继续、提前结束，并把原始数据和 Markdown 报告保存在指定本地目录。

## 小白使用

第一次使用和以后启动都可以双击：

```text
启动火影玩家反馈工具.cmd
```

脚本会在需要时自动安装依赖、构建网页并打开浏览器。网页版默认地址是 `http://127.0.0.1:3765`，仅当前电脑可以访问。工具已经运行时再次双击启动脚本，会直接打开现有网页，不会重复启动服务或报端口占用错误。

真实调查会连接用户日常使用、已经登录 B站的 Chrome。网页会自动发现 Chrome 的本地调试端口、请求浏览器授权并检查 B站登录状态；用户不需要填写 `9222`、输入账号或复制 Cookie。远程调试开关和每次连接的 Chrome 授权提示仍需用户本人确认，工具不会绕过浏览器的安全设置。

第一次使用：

1. 保持普通 Chrome 窗口和 B站登录状态开启。
2. 在工具中点击“开启并连接 Chrome”，按图文提示打开 `chrome://inspect/#remote-debugging` 的远程调试开关。
3. 返回工具点击“连接并检查 B站”，然后在 Chrome 弹窗中点击“允许”。
4. 工具显示账号已连接后即可开始真实调查。

Chrome 连接只监听当前电脑的 `127.0.0.1`。不同电脑会在运行时自动发现各自的动态端口，既不需要相同端口，也不会访问另一台电脑的 Chrome。要求 Chrome 144 或更新版本。

默认调查：

- 实际采集 5 分钟，暂停时间不计入
- 调查最近 30 天发布的内容
- 默认使用 1 个专用调查标签页，可在主页选择 1–4 个并行标签页
- 优先热门视频和动态
- 覆盖多个独立来源后再深入评论
- 数据目录默认为项目下的 `data/`，可在主页通过系统文件夹选择器更改
- 原始 JSONL 以 UTF-8 明文保存，不做整文件加密；公开用户名、UID 与评论同记录保存，便于逐条溯源
- 首次启动会在数据目录创建随机盐，只用于额外生成兼容旧版本的去重键，不替代明文作者字段

选择新位置后，工具会立即切换到该目录并记住选择，但不会移动原目录中的历史文件。高级用户仍可复制 `.env.example` 为 `.env`，通过 `RESEARCH_DATA_DIR` 固定数据目录；启用该配置时，网页中的位置选择会被禁用。

## 主要能力

- 本地 React 网页 UI，无云端服务、无数据库
- Playwright 通过本机 Chrome DevTools Protocol 读取 B站公开可见页面并继承现有登录状态
- 自动读取 Chrome 的 `DevToolsActivePort`，不写死或向用户暴露调试端口
- 主页可选择 1–4 个专用并行标签页；标签页越多，采集更快，但电脑负载和平台限流风险也更高
- 真实调查和虚构演示两种模式
- 采集时长与内容发布时间范围分别配置，可自定义 1–720 分钟
- 原始 JSONL 只追加，派生数据可以重新生成
- 每条新记录带调查 ID；评论同时保存公开用户名、UID、平台评论 ID、父评论 ID、来源页/直达链接和采集时间
- 原子检查点与运行锁，支持安全暂停和跨进程恢复
- 提前终止后直接清洗、分类并生成报告
- 创作者标题与观众评论分开分析
- 多主题、主题级情绪、行为意图和证据门槛
- 网页报告、Markdown 导出和本地文件夹入口
- 历史调查可直接浏览完整意见/来源记录，支持用户名、UID、评论 ID、正文和视频搜索，并可展开原始 JSON

## 开发运行

要求 Node.js 24+ 和本机 Chrome。

```powershell
npm install
npm run build
npm start
```

开发时分别启动后端和 Vite：

```powershell
$env:NO_OPEN="true"
npm run dev
```

另一个终端：

```powershell
npm run dev:web
```

验证：

```powershell
npm test
npm run build
```

## 打包为单个 Windows EXE

开发电脑运行以下命令即可生成免安装便携版：

```powershell
npm install
npm run package:win
```

成品位于 `release/NarutoFeedbackResearch-0.1.0-portable.exe`。把这一个 EXE 复制给其他 Windows 电脑即可；目标电脑不需要安装 Node.js 或项目依赖，但真实调查仍需要 Chrome 144 或更新版本，并由用户按页面提示授权连接已登录的 B站账号。

第一次运行时，Windows SmartScreen 可能会提示“未知发布者”，这是因为当前便携版尚未购买代码签名证书；用户确认来源可信后可选择继续运行。调查数据默认保存在当前 Windows 用户的应用数据目录，也可以在主页中改到其他文件夹。

## 项目结构

```text
config/                         相关性和主题规则
data/runs/<run-id>/             每次调查的独立本地目录
docs/                           研究方案、数据契约和架构说明
src/api/                        本机 Express API
src/collectors/                 B站浏览器与演示采集适配器
src/domain/                     数据类型与输入校验
src/infrastructure/             JSONL、检查点和运行锁
src/processing/                 清洗、规则分类和 Markdown 报告
src/services/                   暂停、恢复和提前生成状态机
web/                            React + Vite 中文 UI
test/                           后端与端到端本地测试
```

## 数据和合规边界

- 只采样公开可见页面，不处理验证码，不绕过登录或访问限制。
- 工具只新建和关闭自己的调查标签页，不导航或关闭用户原有标签页；调查期间 Chrome 授权能够访问整个浏览器配置文件，建议先关闭网银、邮箱等敏感页面。
- 公开用户名、公开 UID 和评论正文会以明文保存在本地，用于把分析结果追溯到原始公开来源；工具不采集 IP 属地等页面未用于研究的额外画像字段。
- 数据目录包含可识别的公开账号信息，使用者应限制目录访问，不要把 `data/runs/` 提交到 Git 或无意分享给他人。
- 热门优先样本不代表全体玩家，报告必须展示来源覆盖和样本限制。
- 规则分类器是可审计的流程基线，正式产品决策前需要人工抽检。
- 演示模式全部为虚构数据，报告会明确标注，不能用于真实判断。

完整方案见 [docs/research-plan.md](docs/research-plan.md)，数据格式见 [docs/data-contract.md](docs/data-contract.md)。
